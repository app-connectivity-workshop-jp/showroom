== Activity: OpenShift Service Mesh でトラフィックを形成する
{m2}

service がロックダウンされ、保護されたので、次は service 間のトラフィックフローに焦点を当てます。

成長する旅行プラットフォームとして、{corp} チームは `discounts` などのコア service に新機能や改善を継続的にロールアウトしており、これらは価格設定やプロモーションに直接影響します。これらの変更は顧客体験と収益に影響するため、更新を安全で観察可能かつ元に戻せる方法でロールアウトすることが重要です。

{rhossm} を活用して、*Canary ロールアウト* などの高度な手法を使用して *トラフィックフローを形成および管理* し、新しいバージョンの service を段階的に導入します。これにより、チームはリスクを最小限に抑えながら、リアルタイムの Observability と制御を得て、安全かつ自信を持って変更をロールアウトできます。

== Activity: Weighted Routing による段階的なトラフィックシフト

この Activity では、`discounts` service の新しいバージョン (`v2`) を導入し、段階的にトラフィックをシフトすることで、実際の *Canary デプロイメント* 戦略をシミュレートします。

NOTE: Canary デプロイメントは、すべての古いインスタンスが置き換えられる前に新しいバージョン (Canary) がテストされる戦略です

image:m2/canary.png[]


次のステップでは、`DestinationRule` と `VirtualService` Istio リソースを作成します。これらのリソースは service 間のトラフィックのルーティング方法を制御し、Canary デプロイメントに不可欠なツールです。これらは service deployments に適用された `version` ラベルに依存して、service の異なるバージョンを識別します。 

== *DestinationRule* を作成する

ここで、`discounts` service の `DestinationRule` を 2 つのバージョン subset (`v1` と `v2`) で定義します。

NOTE: DestinationRule は、ルーティングが発生した後に service に向けられるトラフィックに適用されるポリシーを定義します。名前付き subset を定義することで、バージョン固有のポリシーを指定できます

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーにある *(+)* ボタンをクリックして、新しいリソースを作成します。
+
image:common/create-yaml.png[]
. YAML エディタで、以下の *DestinationRule* CR を貼り付けて、*Create* ボタンをクリックします。

+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: discounts
  namespace: travel-agency
spec:
  host: discounts
  subsets:
  - name: v1
    labels:
      version: v1
  - name: v2
    labels:
      version: v2
----


== *VirtualService* を適用する

次に、最初は 100% のトラフィックを `v1` に、0% を `v2` に送信する `VirtualService` を作成します。

NOTE: VirtualService は、DestinationRule によって作成された subset に基づいてトラフィックをルーティングできるトラフィックルーティングルールのセットを定義します。

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーにある *(+)* ボタンをクリックして、新しいリソースを作成します。
. YAML エディタで、以下の *VirtualService* CR をコピーして、*Create* をクリックします。

+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: discounts
  namespace: travel-agency
spec:
  hosts:
    - discounts
  http:
  - route:
    - destination:
        host: discounts
        subset: v1
        port:
          number: 8000
      weight: 100
    - destination:
        host: discounts
        subset: v2
        port:
          number: 8000
      weight: 0
----

. この VirtualService は現在、*v2* がまだデプロイされていないため、100% のトラフィックをバージョン *v1* にルーティングします。

=== `discounts-v2` Service をデプロイする

`discounts` service の 2 番目のバージョン (`v2`) を mesh にデプロイします。これは既存の `v1` バージョンと並行して実行されますが、ルーティングを設定するまではトラフィックを受信しません。

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーにある *(+)* ボタンをクリックして、新しいリソースを作成します。
. YAML エディタで、以下の *Deployment* CR をコピーして、*Create* をクリックします。
+
YAML の `spec.selector.matchLabels` の下に添付された `version: v2` ラベルに注目してください。
+
[source,sh,role="execute",subs=attributes+]
----
kind: Deployment
apiVersion: apps/v1
metadata:
  name: discounts-v2
  namespace: travel-agency
spec:
  selector:
    matchLabels:
      app: discounts
      version: v2
  replicas: 1
  template:
    metadata:
      annotations:
        readiness.status.sidecar.istio.io/applicationPorts: ""
        proxy.istio.io/config: |
          tracing:
            zipkin:
              address: zipkin.istio-system:9411
            sampling: 10
            custom_tags:
              http.header.portal:
                header:
                  name: portal
              http.header.device:
                header:
                  name: device
              http.header.user:
                header:
                  name: user
              http.header.travel:
                header:
                  name: travel
      labels:
        app: discounts
        version: v2
    spec:
      containers:
        - name: discounts
          image: quay.io/kiali/demo_travels_discounts:v1
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 8000
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop:
              - ALL
            privileged: false
            readOnlyRootFilesystem: true
          env:
            - name: CURRENT_SERVICE
              value: "discounts"
            - name: CURRENT_VERSION
              value: "v2"
            - name: LISTEN_ADDRESS
              value: ":8000"
----

. Deployment が正常に 1 pod にスケールするのを待ちます。
+
image:m2/discounts-v2-deployment.png[]
+
NOTE: `discounts-v2` Deployment CRD の `version: v2` ラベルは、Istio のトラフィックルーティングを有効にするために不可欠です。
