== アクティビティ: OpenShift Service Mesh を有効化する
{m2}

{rhossm} がクラスターにインストールおよび設定されました。これから `travel-agency` Namespace を {rhossm} で管理されるようにオンボードします

=== ワークショップ環境をセットアップする

設定を適用するには、OpenShift コンソールとコマンドラインターミナルにアクセスする必要があります。

// . Make sure you have exited the RHEL server from the previous module. If needed, type `exit` in the lower terminal to exit out of the RHEL system.
// +
// [source,sh,role="execute",subs=attributes+]
// ----
// exit
// ----
. 次のステップで作業しやすくするために、両方のターミナルの出力をクリアします。
+
[source,sh,role="execute",subs=attributes+]
----
clear
----
. 以下のコマンドを使用して、右側の両方のターミナルにログインします。
+
[source,sh,role="execute",subs=attributes+]
----
oc login -u admin -p {ocp_cluster_openshift_cluster_admin_password} https://172.30.0.1:443
----
.. `Use insecure connections? (y/n)` というプロンプトが表示されたら、`y` と入力します
.. `Login successful` というメッセージが表示されます

== `travel-agency` Namespace を確認する

`travel-agency` Namespace の Istio Sidecar Proxy インジェクションを有効にする前に、その中で実行されているすべての Pod を確認しましょう。

. *上部のターミナル* で以下のコマンドを実行します。
+
[source,sh,role="execute",subs=attributes+]
----
oc get pods -n travel-agency
----
+
出力例:
+
----
NAME                             READY   STATUS    RESTARTS   AGE
cars-v1-d7b4b7cf-pm7nh           1/1     Running   0          113m
discounts-v1-7cfd444876-wrxtc    1/1     Running   0          113m
flights-v1-77bbc76cbd-kfghl      1/1     Running   0          112m
hotels-v1-55556b6574-kcxv7       1/1     Running   0          112m
insurances-v1-656cdb54f6-gcc2m   1/1     Running   0          112m
travels-v1-647d788486-wf4nm      1/1     Running   0          112m
----
. 各 Pod の `READY` 列に `1/1` と表示されており、各 Pod に単一のコンテナがあり、実行中であることを示しています。

. Namespace `travel-agency` の設定を確認します。
+
[source,sh,role="execute",subs=attributes+]
----
oc describe namespaces travel-agency
----
+
image:m2/oc-travel-agency.png[]

. ラベル `istio-injection=disabled` を探します
+
[NOTE]
====
`istio-injection=disabled` は暗黙的なデフォルト値であり、デプロイメントに存在しない場合があります。表示されていなくても次のステップに進むことができます。
====

. Istio Sidecar はまだデプロイされておらず、Namespace もまだメッシュに追加されていません。次のステップでそれを変更しましょう。

== `travel-agency` Namespace をメッシュに追加する

Namespace をメッシュにオンボードするには、`travel-agency` Namespace のラベルを手動で編集/パッチするか、Kiali コンソールを使用します。

この Module では、Kiali コンソールを使用して Namespace への自動 Istio インジェクションを有効にします。Service Mesh は、`travel-agency` Namespace 内のすべての Pod に Proxy Sidecar コンテナを自動的にインジェクトし、Service Mesh が Namespace 内のサービスを管理できるようにします。

. http://kiali-istio-system.{ocp_cluster_openshift_cluster_ingress_domain}[Kiali console, window="kiali"] に移動し、プロンプトが表示されたらユーザー名 `admin` とパスワード `{ocp_cluster_openshift_cluster_admin_password}` でログインします。
+
image:m2/kiali-overview.png[link=self, window=blank, width=100%]

. *Namespace* フィルターに `travel-agency` を入力し、*Enter* キーを押してアクションを実行しやすくします。
+
image:m2/namespace-filter.png[]

. `travel-agency` タイルから、ケバブメニュー（3 つの横ドット）をクリックし、*Enable Auto Injection* を選択します。
+
image:m2/kiali-enable-injection.png[]
. *Enable* ボタンをクリックして確認します。
+
image:m2/kiali-enable-injection-button.png[]
. Namespace が更新されたことが通知されます。
このアクションにより、`travel-agency` Namespace がメッシュに追加され、Namespace の Istio ラベルが `istio-injection=enabled` に設定されます。
+
image:m2/kiali-enabled-confirmation.png[] 


=== `travel-agency` への自動インジェクションを検証する

. http://kiali-istio-system.{ocp_cluster_openshift_cluster_ingress_domain}/console/overview?duration=60&refresh=60000&namespace=travel-agency&opLabel=or[Kiali console^, window="kiali"] で、`travel-agency` カードの *labels* リンクをクリックします
+
image:m2/travel-agency-card-7labels.png[]
. 新しいラベル `istio-injection=enabled` が表示されます。
+
image:m2/travel-agency-istioenabled.png[]

=== デプロイメントを再起動して Sidecar をトリガーする

自動インジェクションが有効になったら、アプリケーション Pod を再起動して Sidecar インジェクションをトリガーする必要があります。

. *上部のターミナル* で、以下のコマンドを実行します。これにより、2 秒ごとに `oc get pods` コマンドが自動的に実行されます。
+
[source,sh,role="execute",subs=attributes+]
----
watch oc get pods -n travel-agency
----

. *下部のターミナル* で、以下のコマンドを実行して `travel-agency` Namespace の Pod を再起動します。
+
[source,sh,role="execute",subs=attributes+]
----
oc get deployments -n travel-agency -o name \
  | xargs -I{} oc rollout -n travel-agency restart {}
----
+
下部のターミナルの予想される出力:
+
```
deployment.apps/cars-v1 restarted
deployment.apps/discounts-v1 restarted
deployment.apps/flights-v1 restarted
deployment.apps/hotels-v1 restarted
deployment.apps/insurances-v1 restarted
deployment.apps/travels-v1 restarted
```

. アプリケーションが再起動されると、*上部のターミナル* に Pod ごとに 2 つのコンテナがあることが表示されます。そのうちの 1 つは、自動インジェクトされた Istio Sidecar です。
+

```
NAME                             READY   STATUS    RESTARTS   AGE
cars-v1-8449bdcfcc-27ncs         2/2     Running   0          78s
discounts-v1-f4d97b4b8-78z8w     2/2     Running   0          78s
flights-v1-594f54d7b-lg7n4       2/2     Running   0          77s
hotels-v1-56fc4b478d-lcbn2       2/2     Running   0          77s
insurances-v1-5fc4b7cdf6-khkl5   2/2     Running   0          76s
travels-v1-99798fc94-2xw74       2/2     Running   0          75s
```
. *上部のターミナル* で `Ctrl+C` を使用して `watch` コマンドを停止できます
