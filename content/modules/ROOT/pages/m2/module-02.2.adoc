== Activity: Authorization Policies による最小権限の実装

{m2}

現状では、`travel-agency` namespace 内の microservices は自由に通信できます。これにより開発サイクルは容易になりますが、特に独自の価格ロジックを適用し、機密データを扱う `discounts` のような service にとってはセキュリティリスクとなります。

image:m2/travel-agency-namespace-initial.png[width=70%]

このセクションでは、Istio `AuthorizationPolicy` を適用して最小権限モデルを強制し、許可されたバックエンド service (`hotels`、`cars`、`flights`、`insurance` services) からのみ `discounts` へのアクセスを許可し、`travels` REST API からはアクセスできないようにします。


== *discounts* service の現在のアクセス状況を確認する

. *upper terminal* で以下のコマンドを実行して、`travel-agency` namespace 内のすべての service から `discounts` service に直接アクセスできることを検証します。+
このコマンドは、各 service の pod から直接 `discounts` service を呼び出します。 
+
[source,sh,role="execute",subs=attributes+]
----
oc rsh -n travel-agency $(oc get pod -l app=travels -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-travels

oc rsh -n travel-agency $(oc get pod -l app=flights -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-flights

oc rsh -n travel-agency $(oc get pod -l app=insurances -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-insurances

oc rsh -n travel-agency $(oc get pod -l app=cars -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-cars

oc rsh -n travel-agency $(oc get pod -l app=hotels -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-hotels
----
. 出力は、`travels` REST API や `cars`、`hotels` などの他の service から `discounts` service に直接アクセスできることを検証します。
+
```
{"user":"hello-from-travels","discount":0.05}
{"user":"hello-from-flights","discount":0.05}
{"user":"hello-from-insurances","discount":0.05}
{"user":"hello-from-cars","discount":0.05}
{"user":"hello-from-hotels","discount":0.05}
```

== `discounts` service へのアクセスを制限する

目標は、`discounts` service へのアクセスを制限し、特定のバックエンド service のみがアクセスできるようにし、`travels` REST API からのアクセスを防ぐことです。これは Istio Custom Resource (CR) `AuthorizationPolicy` を使用して実現します。

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーにある *(+)* ボタンをクリックして、新しいリソースを作成します。プロンプトが表示された場合は、ユーザー名 `admin`、パスワード `{ocp_cluster_openshift_cluster_admin_password}` でログインします。
+
image:common/create-yaml.png[]

. YAML エディタで、以下の *AuthorizationPolicy* CR をコピーして、*Create* をクリックします。
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: allow-only-trusted-services
  namespace: travel-agency
spec:
  selector:
    matchLabels:
      app: discounts
      version: v1
  action: ALLOW
  rules:
  - from:
    - source:
        principals:
        - cluster.local/ns/travel-agency/sa/discount-access-sa
----
+
[NOTE]
====
上記の `AuthorizationPolicy` の簡単な説明

* *selector* は workload を指定します。この場合は `discounts` service です
* *action* は設定されたルールに基づいてトラフィックを ALLOW します
* *rules* は `discount-access-sa` という名前の service account を使用している workload からのリクエストを許可します

`discount-access-sa` service account は、workshop セットアップの一部としてすでに作成され、許可されたバックエンド service に追加されています。
====


== *AuthorizationPolicy* をテストする

. *upper terminal* で以下のコマンドを実行して、`travels` REST API が `discounts` service にアクセスできなくなったことを確認します。
+
[source,sh,role="execute",subs=attributes+]
----
oc rsh -n travel-agency $(oc get pod -l app=travels -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-travels && echo
----
. `discounts` service にアクセスできなくなり、代わりに `access denied` レスポンスが返されるはずです。
+
```
RBAC: access denied
```
+
WARNING: AuthorizationPolicy が有効になるまで数秒かかる場合があります。成功レスポンスが表示される場合は、再試行してください。

. *upper terminal* で以下のコマンドを実行して、許可された service が依然として `discounts` service にアクセスできることを検証します。
+
[source,sh,role="execute",subs=attributes+]
----
oc rsh -n travel-agency $(oc get pod -l app=flights -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-flights

oc rsh -n travel-agency $(oc get pod -l app=insurances -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-insurances

oc rsh -n travel-agency $(oc get pod -l app=cars -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-cars

oc rsh -n travel-agency $(oc get pod -l app=hotels -n travel-agency -o jsonpath='{.items[0].metadata.name}') \
  curl http://discounts.travel-agency.svc.cluster.local:8000/discounts/hello-from-hotels
----
+
出力:
+
```
{"user":"hello-from-flights","discount":0.05}
{"user":"hello-from-insurances","discount":0.05}
{"user":"hello-from-cars","discount":0.05}
{"user":"hello-from-hotels","discount":0.05}
```

== まとめ

このセクションでは、Istio `AuthorizationPolicy` を適用して `travel-agency` namespace 内の service 間通信を保護し、{rhossm} がシンプルで宣言的なポリシーモデルを使用してきめ細かなアクセス制御を強制できることを実証しました。
