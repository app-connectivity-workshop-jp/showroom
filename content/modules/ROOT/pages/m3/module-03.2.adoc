== アクティビティ: Developer ワークフロー
{m3}

このセクションでは、開発者の役割を担い、`travel-agency` サービスエンドポイントを安全に公開するためのポリシーを作成します。これにより、パートナーポータルは {corp} のフライト、ホテル、レンタカーのサービスに安全にアクセスできるようになります。

== Travelz Partner Portal アプリケーションへのアクセステスト

. https://travels-blue-ui-travel-web.{ocp_cluster_openshift_cluster_ingress_domain}/[こちら^, console="partner"] をクリックして *Travels Blue* パートナーポータルにアクセスしてください
. `travel-agency` コアサービスエンドポイントが HTTPRoute を使用して公開されておらず、他のアプリケーション/システムで利用できないため、 *404 error* ステータスコードが表示されるはずです。
+
image:m3/partner-blue-404.png[link=self, window=blank, width=100%] 

== Travels サービスエンドポイント用の HTTPRoute のセットアップ

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーの *(+)* ボタンをクリックして、新しい HTTPRoute を作成します。
. YAML エディタで、`travel` REST API 用の次の *HTTPRoute* CR をコピーし、YAML エディタの下部にある Create ボタンをクリックしてください
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: travel-agency
  namespace: travel-agency
  labels:
    deployment: travels-v1
    service: travels
spec:
  parentRefs:
    - group: gateway.networking.k8s.io
      kind: Gateway
      name: prod-web
      namespace: ingress-gateway
  hostnames:
    - api.travels.{ocp_cluster_workshop_main_domain}
  rules:
    - backendRefs:
        - group: ''
          kind: Service
          name: travels
          namespace: travel-agency
          port: 8000
          weight: 1
      matches:
        - path:
            type: PathPrefix
            value: /
----

== HTTPRoute セットアップ後の Web アプリケーションの再テスト

. Web アプリケーションを更新するか、https://travels-blue-ui-travel-web.{ocp_cluster_openshift_cluster_ingress_domain}/[こちら^, console="access Web app"] からアクセスしてください。
. `travels` API の HTTPRoute を作成しましたが、`prod-web` Gateway の `deny-all` デフォルトポリシーが適用され、リクエストが許可されないため、 *403 - Forbidden* エラーが表示されるはずです。zero-trust 認証が設定されています！

image:m3/partner-blue-403.png[link=self, window=blank, width=100%] 


. これは、{rhcl} の {ocp_cluster_openshift_cluster_console_url}/kuadrant/policy-topology[Policy Topology^, window="console"] にアクセスすることで検証できます。`travel-agency` HTTPRoute も Gateway のポリシーを継承していることがわかります（`echo-api` HTTRoute と同じように）

== Authpolicy のセットアップ

次に、パートナーポータルがコアサービスに安全にアクセスできるようにするために、HTTPRoute をターゲットとする AuthPolicy を作成します。

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーの *(+)* ボタンをクリックして、HTTPRoute 用の新しい AuthPolicy を作成します。
. YAML エディタで、AuthPolicy と必要な API Key Secret を作成する次の CR をコピーしてください。 
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: travel-agency-authpolicy
  namespace: travel-agency
spec:
  defaults:
    rules:
      authentication:
        api-key-authn:
          apiKey:
            allNamespaces: false
            selector:
              matchLabels:
                app: partner
          credentials:
            queryString:
              name: APIKEY
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: travel-agency

---
apiVersion: v1
kind: Secret
metadata:
  name: apikey-blue
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: partner
stringData:
  api_key: blue
type: Opaque
----
. *Create* をクリックして、これらのリソースを作成します
. リソースが正常に作成されます。
+
image:m3/auth-apikey-created.png[width=80%]
+
NOTE: このワークショップでは、API Key を使用した認証を選択しました。実際の環境では、リクエストの認証に JWT/OAuth アクセストークンの使用を検討してください。
. {rhcl} の {ocp_cluster_openshift_cluster_console_url}/kuadrant/policy-topology[Policy Topology^, window="console"] にもう一度アクセスしてください。
.. `travel-agency` HTTPRoute が独自の AuthPolicy の影響を受けるようになったことがわかります。
.. また、`prod-web` Gateway の RateLimitPolicy が依然として `travel-agency` HTTPRoute に影響を与えていることもわかります。
+
image:m3/travel-ap-topology.png[]

== デフォルトの RateLimit Policy のテスト
. *Find details* ボタンを 5 回以上クリックしてください。
. 429 エラーが表示されるはずです:
+
image:m3/partner-blue-429.png[link=self, window=blank, width=100%]
. これは、Gateway に設定された非常に低いレート制限が原因です。
. Travels サービス HTTPRoute には特定の RateLimit Policy がないため、Gateway の RateLimit Policy が HTTPRoute にも適用されます。


== 新しい `travels` 専用の RateLimit Policy の作成

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーの *(+)* ボタンをクリックして、HTTPRoute 用の新しい RateLimitPolicy を作成します。
. YAML エディタで、ユーザーごとに 10 秒あたり 20 回の呼び出しという RateLimit Policy を作成する次の CR をコピーしてください。
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: kuadrant.io/v1
kind: RateLimitPolicy
metadata:
  name: ratelimit-policy-travels
  namespace: travel-agency
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: travel-agency
  limits:
    "per-user":
      rates:
        - limit: 20
          window: 10s
      counters:
        - expression: auth.identity.userid
----
. *Create* をクリックしてください。

. *Find details* ボタンをクリックして、詳細に再度アクセスしてみてください。
+
image:m3/webapp-see-details.png[]
. 10 秒間に最大 20 回のリクエストまで、`429 - Too Many Requests` エラーなしで詳細を取得できるはずです。
. {rhcl} の {ocp_cluster_openshift_cluster_console_url}/kuadrant/policy-topology[Policy Topology^, window="console"] では、`travel-agency` HTTPRoute が独自の Auth と RateLimit ポリシーを持ち、Gateway に設定された zero-trust と超低制限を効果的にオーバーライドしていることがわかります。
