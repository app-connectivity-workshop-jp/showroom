== アクティビティ: Platform Engineer ワークフロー
{m3}

ワークショップのこのセクションを実施するには、ターミナル内で OpenShift にログインしていることを確認してください。

. *右上のターミナル* で、次のコマンドを実行すると `admin` と表示されるはずです
+
[source,sh,role="execute",subs=attributes+]
----
oc whoami
----
. そうでない場合は、次のコマンドを実行して OpenShift にログインしてください。
+
[source,sh,role="execute",subs=attributes+]
----
oc login -u admin -p {ocp_cluster_openshift_cluster_admin_password} https://172.30.0.1:443
----

== ワークショップのセットアップ

このモジュールを短時間で完了できるようにするため、一部のコンポーネントとポリシーは事前設定されています。

. *AWS Route 53* に AWS Hosted Zone (DNS ドメイン) `travels.{ocp_cluster_workshop_main_domain}` が作成されています。
. DNS ドメイン `travels.{ocp_cluster_workshop_main_domain}` を参照する Gateway リソース `prod-web`
. {rhcl} Operator といくつかのポリシー（AWS DNS プロバイダーで DNS 管理を提供するため）が事前設定されています。
. `travel-agency` コアサービスのセキュアな外部アクセスをテストするためのサンプルパートナー Web ポータルがデプロイされています

=== Gateway の確認

NOTE: Gateway リソースは、外部トラフィックがクラスタに入る方法を定義し、DNS ドメイン（Hosted Zone）を参照します。

. *Gateways* セクションに表示されている `prod-web` Gateway にアクセスしてください。
+
image:m3/prod-web-snippet.png[link=self, window=blank, width=100%]

. 以下は Gateway の詳細のスニペットです。オプションとして、コンソールの {ocp_cluster_openshift_cluster_console_url}/k8s/ns/ingress-gateway/gateway.networking.k8s.io%7Ev1%7EGateway/prod-web/yaml[YAML タブ^, window=console] に移動して確認することもできます。 
+
[source,sh,subs=attributes+]
----
spec:
  gatewayClassName: istio
  listeners:
    - allowedRoutes:
        namespaces:
          from: All
      hostname: '*.travels.{ocp_cluster_workshop_main_domain}' <1>
      name: api
      port: 443
      protocol: HTTPS
      tls:
        certificateRefs: <2>
          - group: ''
            kind: Secret
            name: api-tls 
        mode: Terminate
----
+
<1> これは、`travels.{ocp_cluster_workshop_main_domain}` ドメインを通じてルーティングされるすべてのトラフィックを処理するワイルドカードホスト名です
<2> TLS Policy が事前に作成されています。これは TLS-issuer を活用して、Gateway 内で定義されたリスナーの TLS 証明書を管理します。


=== DNSPolicy の確認

NOTE: *DNS Policy* は、外部 DNS プロバイダー（この場合は *AWS Route53*）で DNS レコードを管理することで DNS 管理を有効にするために Gateway にアタッチされます。このポリシーは事前に作成されています。なぜなら、新しい DNS レコードの DNS 解決には伝播に時間がかかり、このモジュールでの進行が遅れる可能性があるためです。

. 以下は DNS Policy の詳細のスニペットです
+
[source,sh, subs=attributes+]
----
spec:
  targetRef:
    name: prod-web  <1>
    group: gateway.networking.k8s.io
    kind: Gateway
  providerRefs:
  - name: prod-web-aws-credentials  <2>
----
+
<1> このポリシーが適用される Gateway リソース
<2> DNS レコードを作成できるようにするための DNS プロバイダーの認証情報
+
[TIP]
====
DNS Policies は、特にハイブリッドクラウドアーキテクチャ向けに、デフォルトの Geo Code や負荷分散オプションを含む、より複雑な設定で作成できます。これにより、GitOps アプローチで繰り返し可能な Policy API 設定を使用して、ハイブリッドクラウドアーキテクチャ全体でトラフィックルーティングが可能になります。
====

. オプションとして、コンソールから {ocp_cluster_openshift_cluster_console_url}/k8s/ns/ingress-gateway/kuadrant.io%7Ev1%7EDNSPolicy/prod-web-dnspolicy/yaml[prod-web-dnspolicy, window="console"] に移動することもできます。


=== `echo-api` HTTPRoute へのアクセス

NOTE: HTTPRoute は、すべての受信トラフィックを適切なバックエンドサービスにルーティングするために Gateway にアタッチされます。

. `echo-api` HTTPRoute は、プラットフォームエンジニアが開発者に公開する前にセットアップを検証する方法としてデプロイされています。
. *上部のターミナル* で次の `curl` コマンドを実行して、`echo-api` にアクセスしてください
+
[source,sh,role="execute",subs=attributes+]
----
curl -k -w "%{http_code}" https://echo.travels.{ocp_cluster_workshop_main_domain} && echo
----
. このエンドポイントは認証パラメータなしでアクセス可能で、HTTP `200` の成功レスポンスステータスコードを返すことがわかります。
+
```yaml
{
  "method": "GET",
  ....
  "body": "",
  "headers": {
    "HTTP_HOST": "echo.travels.sandbox4962.opentlc.com",
    "HTTP_USER_AGENT": "curl/7.76.1",
    ....
    "HTTP_VERSION": "HTTP/1.1"
  },
  "uuid": "5dc42712-53c3-4f3d-94ec-9d96a501b213"
}200
```
. これは意図した動作ではなく、対処する必要があります。次のステップでは、このエンドポイントをセキュア化するために *AuthPolicy* を作成します。

== zero-trust AuthPolicy の作成

Platform Engineer として、すべての受信トラフィックをセキュア化するために zero-trust *AuthPolicy* をセットアップします。

NOTE: *Zero trust* は、すべてのインタラクションが信頼されていない状態から始まるセキュリティモデルです


. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーの *(+)* ボタンをクリックして、新しいリソースを作成します。
+
image:common/create-yaml.png[]
. YAML エディタで、次の *AuthPolicy* CR をコピーしてください。
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: prod-web-deny-all
  namespace: ingress-gateway
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: prod-web
  rules:
    authorization:
      deny-all:
        opa:
          rego: "allow = false"
    response:
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied by default by the gateway operator. If you are the administrator of the service, create a specific auth policy for the route."
            }

----
. このポリシーは、すべての受信リクエストを拒否し、レスポンスの一部としてカスタムエラーメッセージを送信します。
. YAML エディタの下部にある *Create* ボタンをクリックします
. *AuthPolicy details* ページの下部までスクロールして、ポリシーが承認され適用されたことを確認してください
+
image:m3/gw-ap-created.png[]

. これまでのセットアップをテストするために `echo-api` HTTPRoute をテストし、セットアップした zero trust ポリシーによりすべてのリクエストが拒否されることを確認します。 *上部* のターミナルで次の `curl` コマンドを実行して `echo-api` にアクセスしてください
+
[source,sh,role="execute",subs=attributes+]
----
curl -k -w "%{http_code}" https://echo.travels.{ocp_cluster_workshop_main_domain} && echo
----
. 成功ではなく、エラーメッセージが表示されるはずです。これは Gateway で設定したエラーメッセージと同じであることに注意してください。
+
```yaml
{
  "error": "Forbidden",
  "message": "Access denied by default by the gateway operator. If you are the administrator of the service, create a specific auth policy for the route."
}
403
```
+
このエラーメッセージは、`API` HTTPRoute がアタッチされている Gateway に適用された zero-trust AuthPolicy が原因です。`echo-api` には他の AuthPolicy がアタッチされていないため、Gateway の AuthPolicy が適用されます。
+
[WARNING]
====
次のようなエラーが発生する可能性があります: `curl: (6) Could not resolve host: echo.travels.sandbo123.opentlc.com`。これは DNS 解決に数分かかる場合があるために発生する可能性があります。1〜2 分後に再度試してください。
====

=== デフォルトの低制限 RateLimitPolicy の作成

NOTE: RateLimitPolicy は、Gateway と HTTPRoute へのリクエストのレート制限を提供し、制限を適用するための詳細なマッチングルールも提供します。

. {ocp_cluster_openshift_cluster_console_url}[OpenShift Console^, window="console"] の上部ナビゲーションバーの *(+)* ボタンをクリックして、新しいリソースを作成します。
+
image:common/create-yaml.png[]
. YAML エディタで、次の RateLimitPolicy CR をコピーして *Create* ボタンをクリックしてください。
+
[source,sh,role="execute",subs=attributes+]
----
apiVersion: kuadrant.io/v1
kind: RateLimitPolicy
metadata:
  name: ingress-gateway-rlp-lowlimits
  namespace: ingress-gateway
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: prod-web
  limits:
    "default-limits":
      rates:
      - limit: 5
        window: 10s
----
. RateLimitPolicy の詳細ページの下部までスクロールして、RateLimitPolicy が承認され適用されたことを確認してください。
+
image:m3/gw-rlp-created.png[]

. オプションとして、*上部* のターミナルで次の `curl` コマンドを実行して `echo-api` にアクセスし、デフォルトのレート制限が適用されているかどうかを確認してください。
+
[source,sh,role="execute",subs=attributes+]
----
for i in {1..10}; do echo "($i)"; curl -k -w "%{http_code}" https://echo.travels.{ocp_cluster_workshop_main_domain}; echo; done
----
+
5 回目の呼び出し以降に **Too Many Requests - 429** メッセージが表示されるはずです

. {rhcl} の {ocp_cluster_openshift_cluster_console_url}/kuadrant/policy-topology[Policy Topology^, window="console"] に移動してください。
+
image:m3/rhcl-topology.png[link=self, window=blank, width=100%]
. Auth、DNS、Rate Limit、TLS ポリシーがすべて `prod-web` Gateway にアタッチされており、`echo-api` HTTRoute によって継承されていることに注意してください。
+
image:m3/echoapi-topology.png[link=self, window=blank, width=100%]

. {ocp_cluster_openshift_cluster_console_url}/kuadrant/overview[Connectivity Link Overview^, window='console'] に移動して、リクエストとエラーに関する統計を表示する更新された *Gateway Traffic Analysis* を確認してください。
+
image:m3/gateway-stats.png[link=self, window=blank, width=100%]
