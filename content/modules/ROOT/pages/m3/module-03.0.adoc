== Module 3: {rhcl} によるトラフィック管理の簡素化とセキュア化
{m3}

人気の高まりに伴い、{corp} は既存のポータルに新しいチャネルを追加したいと考えています。彼らは、フライト、レンタカー、ホテルサービスへのセキュアなアクセスを必要とする旅行パートナーのオンボーディングを計画しています。

外部のパートナーポータルからの全ての受信トラフィックは、セキュア化され管理される必要があります。{corp} は、システムやユーザーに基づいて、レート制限や特定のアクセスレベルを簡単に適用することでエンドポイントを保護したいと考えています。


== ソリューション概要

コアサービスを外部の旅行パートナーに安全に公開するため、{corp} は policy-as-code アプローチを採用することにしました。このアプローチは、受信する North-South トラフィックに適用できるポリシーを管理する反復可能で自動化された方法を提供し、コードを通じてセキュリティを簡単に定義できるようにします。

チームは、マルチクラスタ環境全体でセキュアなトラフィック管理を可能にするため、https://kuadrant.io/[Kuadrant^, window='content'] オープンソースプロジェクトをベースにした {rhcl} を採用します。

{rhcl} は、Kubernetes の新しい Ingress 標準である https://gateway-api.sigs.k8s.io/[*Gateway API*^, window='content'] の機能を拡張します。DNS 管理、TLS 証明書のライフサイクル管理、認証、レート制限をサポートする Policy API を提供します。

image:m3/m3-soln.png[link=self, window=blank, width=100%]


{rhcl} ポリシーは、Gateway と HTTPRoute リソースを使用して、Service にルーティングされる HTTP トラフィックに適用されます。

image:m3/rhcl-policies.png[link=self, window=blank, width=100%]

プラットフォームエンジニアは、Gateway にポリシーを適用することで、より具体的なポリシーが適用されるまで、ネットワークの下位レベル（HTTPRoute/Services）を管理できます。

このアプローチにより、プラットフォームエンジニアとアプリケーション開発者は協力して、公開されたエンドポイントを保護するために必要な適切なポリシーを通じて、分散されたサービスとアプリケーションを接続、セキュア化、保護できます。

== アクティビティ概要

次のセクションでは、プラットフォームエンジニアと開発者として、サードパーティパートナーアクセスのために `travel-agency` コアサービスをセキュア化するアクティビティを実施します。

. *Platform Engineer* として、Gateway リソースに対するセキュリティガードレールとして適切なポリシーをセットアップし、トラフィックフローが zero trust ポリシーでセキュア化されていることを検証します。
. *Application Developer* として、`travel-agency` サービスルートを安全に公開し、コアサービスのエンドポイントへのセキュアなアクセスを許可する特定のポリシーを適用します。
. ビジネスオーナー、プラットフォームエンジニア、アプリケーション開発者向けの詳細な可観測性のために Grafana ダッシュボードを確認します。
