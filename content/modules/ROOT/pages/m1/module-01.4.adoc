== アクティビティ: サービスからのデータベースアクセスを検証する
{m1}

これで、travels サービスがデータベースにアクセスできるかどうかを検証する準備が整いました。ワークショップのセットアップの一環として、travels サービスは OpenShift 上の {rhsi} Listener に接続するように既に設定されており、これは実際のオンプレミスデータベースの仮想エンドポイントとして機能します。

. *OpenShift ターミナル（上部のターミナル）* で、以下の curl コマンドを再度実行して、都市 *Prague* の旅行見積もりを取得し、サービスがオンプレミスデータベースにアクセスできるかどうかを確認します。
+
[source,sh,role="execute",subs=attributes+]
----
curl travels.travel-agency.svc.cluster.local:8000/travels/Prague | jq
----

. データベースから返された cars、hotels、flights、insurances を含む応答が表示され、サービスがデータベースにアクセスできることを示します。
+
image:m1/travel-agency-response.png[]

== Network Console を確認する

. https://skupper-network-observer-travel-db.{ocp_cluster_openshift_cluster_ingress_domain}/[Service Interconnect Network Console, window="network-console"] に戻り、ブラウザタブを更新します。RHEL サーバーが Virtual Application Network の一部になったことを確認します。
+
image::m1/complete_console.png[]

. Services、Sites、Components、Processes などの Service Interconnect Network Console のさまざまなオプションを自由に確認して、Virtual Application Network とトラフィック関連の分析について理解を深めてください。

== {corp} の次のステップ
{corp} がデータベースレプリカを別の環境またはクラスターに追加することを決定した場合、既存の Virtual Application Network に追加して、OpenShift の同じ Listener にリンクするだけで済みます。Red Hat Service Interconnect は、データベースインスタンス間のフェイルオーバーと負荷分散を自動的に処理します。
