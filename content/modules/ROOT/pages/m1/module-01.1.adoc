== アクティビティ: OpenShift で {rhsi} をセットアップする
{m1}

{rhsi} を使用して Virtual Application Network をセットアップするには、コマンドラインインターフェースまたは OpenShift Operator のいずれかを使用できます。

この演習では、両方のオプションを試すために、OpenShift クラスターでは Operator を使用し、RHEL 側ではコマンドラインインターフェースを使用します。Ansible などの自動化ツールを使用して、両側での Virtual Application Network の作成を自動化することもできます。



== Travels Service からのデータベースアクセスを検証する

. 最初のステップとして、`travels` サービスがデータベースへの接続性を持っているかどうかを確認します。ガイドに従って、右側の統合ターミナルを使用してこれらのチェックを実行します。

. *上部のターミナル* で、以下のコマンドを使用して OpenShift クラスターにログインします。クリップボードアイコン image:common/clipboard.png[width=30px] をクリックしてコピーします。
+
[source,sh,role="execute",subs=attributes+]
----
oc login -u admin -p {ocp_cluster_openshift_cluster_admin_password} https://172.30.0.1:443
----

+
`Use insecure connections? (y/n)` というプロンプトが表示されたら、`y` と入力します。+
`Login successful` というメッセージが表示されます

. *OpenShift ターミナル（上部のターミナル）* から、以下のコマンドを実行して、`travels` サービスおよびその他すべてのサービス（cars、discounts など）がオンプレミスデータベースにアクセスできるかどうかを確認します。
+
[source,sh,role="execute",subs=attributes+]
----
curl travels.travel-agency.svc.cluster.local:8000/travels/Prague && echo
----

. データベースにアクセスできず、サービスが Prague の旅行見積もりを取得できないことを示す `{"error":"Travel Quote for Prague not found"}` という応答を受け取ります。 

== {rhsi} Site をセットアップする

以降のステップで {rhsi} を使用して Virtual Application Network をセットアップし、コアサービス（OpenShift 上）がオンプレミスデータベースにアクセスできるようにします。

. {ocp_cluster_openshift_cluster_console_url}/k8s/cluster/projects/travel-db/openshift-site-plugin[OpenShift Console, window="console"] に移動し、ユーザー名 `admin` とパスワード `{ocp_cluster_openshift_cluster_admin_password}` でログインします

. まだ `travel-db` プロジェクトにいない場合は、Home -> Projects -> travel-db に移動します。
+
image::m1/projects_tab.png[link=self, window=blank, width=100%]
. `travel-db` プロジェクトから、*Service Interconnect tab* をクリックするか、この {ocp_cluster_openshift_cluster_console_url}/k8s/cluster/projects/travel-db/openshift-site-plugin[link, window="console"] をクリックして直接移動します。
. *Create site* をクリックします。
+
image::m1/site_button.png[]
+
[.concept]
.Site とは何ですか？
****
Site は、実際に実行中のワークロードがある場所を表します。各 Site には、そのワークロードがリモート Site のワークロードと接続するのを助けるアプリケーションサービスルーターが含まれています。例: Namespace は Site です
****
. *Create site* ウィザードで、デフォルト値を保持します。
.. *Enable link access* がチェックされていることに注意してください。これは、この Site が他の Site からの Ingress 接続を許可することを示しています。
.. *Submit* をクリックして、`travel-db` Namespace に VAN ルーターをセットアップします。
+
image::m1/create_site.png[]
+
[.concept]
.Router とは何ですか？
****
Layer 7 アプリケーションルーターは、従来のネットワークルーターが VPN のバックボーンを形成するのと同じように、VAN のバックボーンを形成します。ただし、ネットワークエンドポイント間で IP パケットをルーティングする代わりに、Layer 7 アプリケーションルーターはアプリケーションエンドポイント（Layer 7 アプリケーションアドレスと呼ばれる）間でメッセージをルーティングします。
****


. *Service Interconnect site* が作成されていることを示すメッセージが表示されます。数秒で警告メッセージが消え、Site が作成されます。
+
image::m1/site_create_warning.png[]

. Site が作成されると、警告メッセージが消えます。
+
image::m1/site_created.png[]
+
*Details* タブに `Ready` ステータスが表示され、Site が準備完了であることが確認できます。
+
image:m1/site-ready.png[] 

== {rhsi} Listener をセットアップする

[.concept]
.Listener とは何ですか？
****
Listener は、ルーティングキーを使用してリモート Site の Connector にリンクするローカル接続ポイントを作成します。Kubernetes では Service として実装され、Docker、Podman、Linux ではローカルネットワークインターフェースのリスニングソケットとして実装されます。Listener は、ルーティングキーを使用してリモート Site と接続しながら、ローカルクライアント向けにホスト/ポートを公開します。
****
image::m1/connector_image.png[]

. {ocp_cluster_openshift_cluster_console_url}/k8s/cluster/projects/travel-db/openshift-site-plugin[Create listener, window="console"] をクリックして、`travel-db` Namespace に Listener をセットアップします。
+
image::m1/listener_button.png[]

. 以下の詳細を入力し、*Submit* をクリックします
** *Name*: `mysqldb`
** *Port*: `3306`
** *Routing key*: `appconn`
** *Host*: `mysqldb`
** *TLS secret*: 後のステップでトークンを作成するため、今は空白のままにします。
+
image::m1/listener_form.png[]

== Access Token をセットアップする

[.concept]
.Access Token とは何ですか？
****
Access Token は、Site 間のリンクを作成するための短期間有効な認証情報です。Access Grant からの URL とシークレットコードが含まれています。トークンの有効性は限定的で、デフォルトでは 1 回のみ使用でき、15 分後に期限切れになります。
****
.Access Grant とは何ですか？
****
リンクを受け入れたい Site (Site 1) は Access Grant を作成します。
それを使用して対応する Access Token を発行し、リモート Site (Site 2) に転送します。
Site 2 は Access Token を Site 1 に提出して引き換えます。
トークンが有効な場合、Site 1 は Site 2 に Site 1 へのリンクを作成するために必要な TLS ホスト、ポート、認証情報を送信します
****
この画像は、この概念をより詳しく説明しています。

image::m1/token_redemption.png[]

. {ocp_cluster_openshift_cluster_console_url}/k8s/cluster/projects/travel-db/openshift-site-plugin[Generate a token, window="console"] をクリックします。
+
image::m1/token_button.png[]

. *Issue Access Token* ウィザードが表示されます。 *Configuration* ステップで、以下の値を入力し、*Create* ボタンをクリックします。
** *FileName*: `my-grant`
** *Redemptions*: `1`
** *Code*: 空白のままにします
** *Valid for*: `60` minutes
+
image:m1/create-access-token.png[]
. *Create token - How to* ステップが表示されます。
.. ファイルをダウンロードする必要なく、スクリプトを使用して Grant を直接変換し、オンプレミス RHEL サーバーに転送するため、残りのステップは無視できます。
.. トークンの内容を確認したい場合は、ファイルをダウンロードして開くこともできます。
.. *Done* をクリックします。
+
image::m1/token_done_screen.png[]

. *OpenShift ターミナル（上部のターミナル）* から、以下のコマンドを実行して ** {rhsi} Network Console** をデプロイします。
+
[source,sh,role="execute",subs=attributes+]
----
oc apply -f https://raw.githubusercontent.com/app-connectivity-workshop/scripts/refs/heads/main/m1/network_console_deploy.yaml -n travel-db
----
+
このコンソールは後でネットワークを可視化するために使用します。初期化に数秒かかるため、今すぐデプロイしてください。デプロイされている間に、時間を節約するために次のステップに進みます。
