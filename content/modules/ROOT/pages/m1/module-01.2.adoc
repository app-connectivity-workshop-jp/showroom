== アクティビティ: RHEL で {rhsi} をセットアップする
{m1}

OpenShift Site と同様に、RHEL で Site とルーターをセットアップしますが、このアクティビティでは {rhsi} コマンドラインインターフェースを使用します。

=== RHEL にログインして環境を検証する

. ページの **右下** にある組み込みターミナルを使用して、オンプレミス RHEL サーバーに SSH 接続する必要があります。
+
image::m1/lower_terminal.png[]

. *下部のターミナル* を使用して、以下のコマンドで RHEL サーバーにログインします。
+
[source,sh,role="execute",subs=attributes+]
----
ssh -o ServerAliveInterval=60 \
    -o ServerAliveCountMax=60 lab-user@{rhel_hostname}
----


. `Are you sure you want to continue connecting (yes/no/fingerprint)?` というメッセージが表示されたら、`yes` と入力して Enter キーを押します

. *Failed to add the host to the list of known hosts (/data/.ssh/known_hosts).* というメッセージは無視してください

. プロンプトが表示されたら、パスワード `{rhel_ssh_password}` を入力し、*Enter* キーを押します。
+
これで RHEL サーバーにログインしました。データベースと OpenShift クラスター間のリンクをセットアップする方法を見てみましょう。
+
image::m1/rhel_user.png[]

. 以下のコマンドを入力して *RHEL ターミナル（下部のターミナル）* をクリアします
+
[source,sh,role="execute",subs=attributes+]
----
clear
----

. **RHEL サーバー** でデータベースが実行されているかどうかを確認するには、*RHEL ターミナル（下部のターミナル）* から以下のコマンドを実行します。
+
[source,sh,role="execute",subs=attributes+]
----
podman ps
----

. 以下のような出力が表示されます。
+
[source,sh,subs=attributes+]
----
CONTAINER ID   IMAGE        COMMAND   CREATED   STATUS    PORTS    NAMES
3d12164dd54b  quay.io/kiali/demo_travels_mysqldb:v1  --default-authent...  4 hours ago  Up 4 hours  0.0.0.0:3306->3306/tcp, 3306/tcp, 33060/tcp  travels-mysqldb
----
+
[CAUTION]
====
.出力が空のリストを返す場合はここをクリックしてください
[%collapsible]
=====
出力が空のリストを返す場合は、RHEL サーバーでデータベースが実行されていないことを示しています。 *下部のターミナル* で以下のコマンドを実行してデータベースを再起動します。

[source,sh,role="execute",subs=attributes+]
----
podman restart travels-mysqldb
----

以下のコマンドを再度実行して、データベースが実際に実行されていることを検証します。
[source,sh,role="execute",subs=attributes+]
----
podman ps
----
=====
====

=== {rhsi} Site を作成する

. *RHEL ターミナル（下部のターミナル）* で、以下のコマンドを実行して Site を作成します。OpenShift Site と同様に、これにより VAN ルーターがセットアップされます。
+
[source,sh,role="execute",subs=attributes+]
----
export SKUPPER_PLATFORM=podman
skupper site create rhel
----

. 以下の出力が表示されます。
+
[source,sh,subs=attributes+]
----
File written to /home/lab-user/.local/share/skupper/namespaces/default/input/resources/sites/rhel.yaml
----

=== Connector を作成する

次に、Connector とは何かを学び、作成してみましょう。

[.concept]
.Connector とは何ですか？
****
Connector は、ルーティングキーを使用してローカルワークロードをリモート Site の Listener にリンクします。Kubernetes では通常 Pod Selector を使用し、Docker、Podman、Linux ではホストとポートの仕様を使用します。ルーティングキーは、Connector をリモート Site の一致する Listener にバインドする文字列識別子です。
****
image::m1/connector_image.png[]


. *RHEL ターミナル（下部のターミナル）* で、以下のコマンドを実行してデータベース用の Connector を作成します。
+
[source,sh,role="execute",subs=attributes+]
----
skupper connector create mysqldb 3306 --host 127.0.0.1 -r appconn
----

. 以下の出力が表示されます。
+
[source,sh,subs=attributes+]
----
File written to /home/lab-user/.local/share/skupper/namespaces/default/input/resources/connectors/mysqldb.yaml
----


== {rhsi} Network Console でセットアップを可視化する

Virtual Application Network を作成する最終ステップに進む前に、https://skupper-network-observer-travel-db.{ocp_cluster_openshift_cluster_ingress_domain}/[Service Interconnect Network Console, window="network-console"] に移動して、これまでにセットアップした設定に基づいて *Virtual Application Network* を可視化します。

. *Log in with OpenShift* をクリックし、プロンプトが表示されたらユーザー名 `admin` とパスワード `{ocp_cluster_openshift_cluster_admin_password}` でログインします。

. *Allow selected permissions* をクリックします。
+
image::m1/allow_permission.png[]

. 現時点では、OpenShift クラスター（travel-db Namespace）のみが表示されます。これは、RHEL オンプレミスマシンがまだ Virtual Application Network の一部ではないためです。
+
image::m1/network-console-ocp.png[]
