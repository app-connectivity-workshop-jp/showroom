== Module 1: {rhsi} でオンプレミスとクラウド間のアプリケーションを接続する
{m1}

{corp} は、規制要件のためにコアデータベースをオンプレミスに保持しながら、Red Hat OpenShift を使用してモノリシックアプリケーションからマイクロサービスへの移行を進めています。

マイクロサービス（OpenShift 上）とデータベース（Red Hat Enterprise Linux (RHEL) 上）が異なる物理ネットワーク上で実行されているため、複雑な計画と管理が必要な従来の VPN を実装する代わりに、*{rhsi}* を選択してこれらの環境間に安全な Virtual Application Network (VAN) を作成します。

{rhsi} は、Open Systems Interconnection (OSI) モデルの Application Layer である Layer 7（レイヤー7）を通じて接続性を実現し、分散サービス間に数分で VAN を作成し、すべての相互接続を Mutual TLS (mTLS) で保護します。

*従来の VPN に対する Layer 7 VAN の利点:*

* VAN はネットワーク層全体ではなくサービスのみを公開するため、必要なファイアウォールルールが少なくて済みます。一方、従来の VPN はクラスター全体を接続するため、VAN と同じレベルの分離を実現するには、アプリケーションごとに広範で時間のかかるファイアウォールルールが必要です。
* VAN では、各サイトが独自の Certificate Authority (CA) を持つため、セキュリティ侵害が限定されます
* VAN では公開されたサービスのみにアクセスできるため、侵害が発生した場合の不正な横方向の移動を防ぎます

== ソリューション概要

この Module では、パブリッククラウド（この場合は AWS）の OpenShift 上で実行されている {corp} のコアサービスと、RHEL 上で実行されている travels データベース（`travels-db`）との間に Virtual Application Network をセットアップする手順をご案内します。

{rhsi} を使用すると、コアマイクロサービス（OpenShift 上）は、データベースが OpenShift 内のローカルサービスであるかのように `travels-db`（RHEL 上）に接続できます。

== アクティビティ概要:

. OpenShift と RHEL の両方で Service Interconnect ルーターをセットアップする

. OpenShift クラスターで作成された安全なトークンを RHEL サーバーに交換して、2 つのマシン間の安全な接続を確立する

. マイクロサービスが、OpenShift クラスター上の Service Interconnect によって作成された Listener（仮想エンドポイント）を使用してリモートデータベースにアクセスできることを検証する
